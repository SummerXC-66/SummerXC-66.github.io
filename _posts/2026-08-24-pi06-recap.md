Physical Intelligence 的 **RECAP**（RL with Experience and Corrections via Advantage-conditioned Policies）把 VLA 的强化学习改成「带优势标签的条件监督学习」。配套模型是 **π\*0.6**：在 π0.6 上增加二值优势条件 `I_t`。

论文：[π\*0.6: a VLA That Learns From Experience](https://arxiv.org/abs/2511.14759)

核心做法：价值函数给每段经验打「比预期好 / 差」的标签，策略同时学会好行为和坏行为；部署时永远条件在 `Advantage: positive` 上。

## 一、三步循环

每一轮改进只做三件事，数据变了，子程序不变：

1. **采集数据**：用当前策略上机跑任务，标成功 / 失败；可选专家中途接管纠正。
2. **训价值函数**：用目前全部数据学「离成功还剩多少步」。
3. **优势条件训策略**：把优势压成 `positive / negative`，作为文本前缀做监督学习。

数据来源三类一起用：人类示范、自主 rollout（成功和失败都留）、部署中的 human-gated DAgger 纠正。

## 二、完整流程（Algorithm 1）

```
输入：多任务示范集 D_demo

# 预训练（offline RL）
1. 用 Eq.1 在 D_demo 上训价值函数 V_pre
2. 用 Eq.3 + V_pre 训策略 π_pre

# 下游任务 specialization
3. 用任务 ℓ 的示范初始化 D_ℓ
4. 从 V_pre 微调 V_ℓ^0
5. 从 π_pre 微调 π_ℓ^0
   （这一步常把 I_t 全标成 True，等价 SFT）

# 迭代自我改进
for k = 1 … K:
    用 π_ℓ^{k-1} 上机采集，并入 D_ℓ
    从 V_pre 在全部 D_ℓ 上重训 V_ℓ^k
    从 π_pre 在全部 D_ℓ 上用新优势标签重训 π_ℓ^k
```

实现上，每一轮 value 和 policy 都从**预训练 checkpoint** 微调，而不是从上一轮继续训，用来压 drift。很多任务一轮就有明显提升。

---

## 三、步骤 1：稀疏奖励

每条 episode 只需要一个成功 / 失败标签。奖励定义为「离成功还剩多少步」：

```
r_t =
  0            若 t = T 且成功
  -C_fail      若 t = T 且失败
  -1           其他时刻
```

成功轨迹上，return 就是「还要几步完成」的负数；失败轨迹会被压到很负。不同时长的任务按最大 episode 长度把价值归一化到 `(-1, 0)`。

不需要手写稠密 reward。

---

## 四、步骤 2：训价值函数（Eq.1）

`p_φ(V | o_t, ℓ)` 是 **201 bin 的分布价值函数**（更小的 Gemma 3，约 670M），输入观测和语言指令，输出离散价值分布。

用 Monte Carlo return 做交叉熵：

```
min_φ  E_{τ ∈ D}  Σ_{o_t ∈ τ}  H( R_t^B(τ),  p_φ(V | o_t, ℓ) )
```

连续价值取分布期望。预训练阶段 `D` 是示范；后续迭代是示范 + 自主经验 + 纠正的混合。

价值函数是「离成功还有多远」的 GPS：成功轨迹上逐步升到 0，失败或卡死处会明显掉下去。

---

## 五、步骤 3：算优势并二值化

```
A(o_t, a_t) = 实际回报 − V(o_t)
```

| 阶段 | 怎么算 |
|------|--------|
| 预训练 | 整条轨迹 return（`N = T`），方便在线一次推断 |
| 微调 | n-step，`N = 50` |

再二值化成改进指示：

```
I_t = 1( A > ε_ℓ )
```

阈值 `ε_ℓ` 按任务分位数设：

| 阶段 | 大约多少标 positive |
|------|---------------------|
| 预训练 | 30% |
| 微调 | 40% |
| 已经很成功但太慢（如衬衫折叠） | 可压到约 10%，逼策略变快 |

**人类纠正强制 `I_t = True`**，默认专家接管动作是好动作。整条 episode（自主段 + 纠正段）都可进数据集。

---

## 六、步骤 4：优势条件训策略（Eq.3）

改进策略可以写成：

```
π̂(a | o, ℓ)  ∝  π_ref(a | o, ℓ) · [ π_ref(a | I, o, ℓ) / π_ref(a | o, ℓ) ]^β
```

当 **β = 1** 时，直接等于条件策略 `π_ref(a | I, o, ℓ)`。所以不必对 log-prob 求导，改成同时学会无条件和有条件两个分布（类似 CFG）：

```
min_θ  E[ −log π_θ(a | o, ℓ) − α log π_θ(a | I, o, ℓ) ]
```

实现：在文本前缀里加一句，插在子任务预测 `ℓ̂` 之后、动作之前：

- `Advantage: positive`
- `Advantage: negative`

训练时 **30% dropout 掉这个指示**，以便推理时既能直接喂 `positive`，也能做 classifier-free guidance。

连续动作用 flow matching 损失当下界，和 FAST 离散动作交叉熵加在一起。人类纠正与失败 rollout 都参与训练：负样本用来学「不要这样做」。

---

## 七、步骤 5：部署

推理永远条件在 **positive** 上：

1. 默认喂 `Advantage: positive`（β = 1）。
2. 可选 CFG：用条件与无条件 flow 的差把 β 提到 1.5–2.5。β 太大容易把动作推到分布边缘，动作会过猛。

然后用新策略再采集、再训 value、再训 policy。

---

## 八、为什么不用 PPO / AWR

| 方法 | 问题 |
|------|------|
| PPO / 策略梯度 | flow matching 没有稳定 log-prob；真机接近 offline，trust region 难调 |
| AWR | 按优势加权回归，大量负样本被丢掉，等于 filtered BC，速度上不去 |
| RECAP | **全部数据都做监督**，只是多一个正 / 负标签 |

同样数据上，论文里 RECAP 的吞吐高于 AWR 和 PPO。

---

## 九、和 π0.6 的关系

π\*0.6 仍是 π0.5 / π0.6 那套 Knowledge Insulation：

- Gemma 3 4B 做视觉语言 + 子任务文本 + FAST 离散动作
- 独立 860M action expert 做 50 Hz flow matching 连续动作，stop-gradient 防止动作头污染 backbone
- 相对 π0.5：更多机器人平台数据、更大 action expert、以及 RECAP 用的优势条件 `I_t`

一句话串起来：

```
示范 / 自主尝试 / 专家纠正
        ↓
价值函数：预测「还要多久成功」
        ↓
优势 = 实际进展 − 预期进展  →  Positive / Negative
        ↓
VLA 条件监督学习这两种模式
        ↓
部署只采样 Positive（可选 CFG）
        ↓
再采集、再训 value、再训 policy（从预训练权重重启）
```
