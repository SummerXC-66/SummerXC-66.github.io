PPO：**旧策略进关打数据，新策略只许小步改按键概率。** 公式和下面的 Python 一一对应。完整可跑代码见 [vietnh1009/Super-mario-bros-PPO-pytorch](https://github.com/vietnh1009/Super-mario-bros-PPO-pytorch)（`train.py`）。

```bash
python train.py --world 1 --stage 1 --lr 1e-4
```

环境是 `gym-super-mario-bros`。默认：8 个并行关卡、每轮采 512 步、回放 10 个 epoch、clip ε = 0.2。

## 过程与需要的模型

一轮就四步：

1. **采集：** 当前网络当旧策略 π_old，进关打 512 步，记下画面、按键、奖励、V、log π_old
2. **打分：** 用 GAE 从后往前算出每一步的优势 A（比这屏平均好多少）
3. **更新：** 同一批数据回放几个 epoch；新策略 π_new 再算这些旧键的概率，clip 锁住比值，同时拟合 V、加一点熵
4. **丢掉重打：** 参数已变，旧录像作废，带着新网络再进关

**需要的模型只有一个：** `src/model.py` 里的 `PPO`（Actor-Critic）。不是两套独立网络，也没有 DQN 那种 target 网络。旧策略不另存一份权重，只把采集时的 `log_prob` 冻住。

| 要不要单独建 | 是什么 | 干什么 |
|--------------|--------|--------|
| 要（一个类） | `PPO`：共享 CNN + 两个头 | 看 4 帧画面，同时出按键和分数 |
| 其中一头 | actor（`actor_linear`） | 策略 π：各键 logits → 采样、log-prob、clip 比值 |
| 其中一头 | critic（`critic_linear`） | 价值 V：这屏大概能拿多少分，给 GAE 当基线 |
| 不要另建 | π_old 网络 | 用冻住的 `old_log_pis` 代替 |
| 不要另建 | target / 裁判网络 | PPO 不靠第二套价值网 |
| 不是网络 | 马里奥环境 | 给画面和奖励，不训练 |

`forward` 一次返回 `(logits, value)`，采集和更新都走这同一个 `model`。结构见下面第二节和仓库 README。

## 一、画面、按键、奖励

仓库把彩色帧转成 84×84 灰度，再叠 4 帧当状态；`JoypadSpace` + `SIMPLE_MOVEMENT` 把按键收成大约 7 个离散动作（右、跳、跑跳等）。奖励大致是：向右 / 得分加分，撞死或掉坑减分，插旗再加一笔。

```python
import gym_super_mario_bros
from nes_py.wrappers import JoypadSpace
from gym_super_mario_bros.actions import SIMPLE_MOVEMENT

env = gym_super_mario_bros.make("SuperMarioBros-1-1-v0")
env = JoypadSpace(env, SIMPLE_MOVEMENT)  # a = 0..6 某个按键组合
s = env.reset()                          # 处理后: (4, 84, 84)
s, r, done, info = env.step(a)           # r: 这一下得分; info["x_pos"] 是向右走了多远
```

| 代码 | 公式里 | 马里奥 |
|------|--------|--------|
| `s` | 状态 | 最近 4 帧画面 |
| `a` | 动作 | 一个按键组合 |
| `r` | 奖励 | 向右、金币、死、插旗 |
| `logits` | 未归一化的 π | 各按键有多想按 |
| `value` | V(s) | 这屏后面大概能拿多少分 |
| `adv` | A | 这一下比「这屏平均」好多少 |

目标仍是整局折扣回报尽量大：

$$
J(\theta)=\mathbb{E}\Big[\sum_{t}\gamma^{t}r_{t}\Big]
$$

## 二、网络：一屏出「按什么」和「值多少」

仓库 `src/model.py`：四层 CNN 后分两个头。类定义和张量形状见仓库 [README](https://github.com/SummerXC-66/SummerXC-66.github.io#ppo-马里奥model-结构与定义)。

```
(B, 4, 84, 84) → 4×Conv(32, stride=2) → Linear 512
                 ├─ actor  → logits [B, 7]
                 └─ critic → value  [B, 1]
```

```python
# 对应 model.py 的 PPO.forward
logits, value = model(s)          # logits: [B, 7]    value: [B, 1]
dist = Categorical(logits=logits) # π_θ(a|s) = softmax(logits)
a = dist.sample()                 # 按概率抽一个键
log_pi = dist.log_prob(a)         # log π_θ(a|s)，后面算比值要用
```

`logits` 是策略（决定按哪个键），`value` 是评论家（这屏大概能拿多少分，给 GAE 当基线）。两个头共享看画面的 CNN。没有 critic，优势只能用整局回报，方差会很大；没有 actor，就没有可更新的按键分布。

## 三、采集：旧策略打 512 步

这一节**不算梯度**，只进关、按键、记账。此时网络还没更新，就是旧策略 π_old。仓库默认 `num_local_steps=512`：连续玩 512 下，得到一条「旧打法」的录像。

每一步只做三件事：看画面 → 按旧策略抽一个键 → 环境返回奖励和下一步。

$$
a_{t}\sim\pi_{\mathrm{old}}(\cdot\mid s_{t})
$$

$$
s_{t+1},\;r_{t},\;d_{t}=\mathrm{env.step}(a_{t})
$$

d_t = 1 表示这一下死了或过关，下一帧要 `reset`。

策略本身是对 actor 的 logits 做 softmax：

$$
\pi_{\mathrm{old}}(a\mid s_{t})=\mathrm{softmax}(\mathrm{logits}_{t})_{a}
$$

代码里 `Categorical` 就是这个分布。抽到的那个键还要记下对数概率，后面算新旧比值用：

$$
\log\pi_{\mathrm{old}}(a_{t}\mid s_{t})
$$

同一屏 critic 再估一个分数，后面 GAE 当基线：

$$
V(s_{t})
$$

对应 `train.py` 的采集循环：

```python
# 对应 train.py 里 for _ in range(num_local_steps)
old_log_pis, actions, values, rewards, dones = [], [], [], [], []

for t in range(512):
    logits, value = model(s)               # logits → π_old ; value → V(s_t)
    dist = Categorical(logits=logits)
    a = dist.sample()                      # a_t ~ π_old
    old_log_pis.append(dist.log_prob(a))   # log π_old(a_t|s_t)
    values.append(value)                   # V(s_t)
    s, r, done, _ = env.step(a.item())     # s_{t+1}, r_t, d_t
    actions.append(a)
    rewards.append(r)
    dones.append(done)
    if done:
        s = env.reset()
```

512 步结束后，手里是 5 列对齐的数（每列长度 512）：

| 存下来的 | 公式 | 后面谁用 |
|----------|------|----------|
| `actions` | a_t | 更新时问新策略：旧键现在概率多少 |
| `old_log_pis` | log π_old(a_t\|s_t) | 和新 log 相减，得到 ratio |
| `values` | V(s_t) | 算优势 A、价值标签 |
| `rewards` | r_t | 算优势 A |
| `dones` | d_t | 死亡处截断，不把下一局的分接过来 |

这里还没有优势 A，也还没有 clip。采集只负责把 π_old 的轨迹记全；A 在第四节用 r 和 V 往回算，梯度在第五节才出现。

为什么必须是「旧」策略：这 512 步是当前网络打出来的。一更新，网络就变成 π_new，这批录像的概率对不上，所以要把当时的 `log_prob` 冻住（`.detach()`），当 π_old。

## 四、GAE：给每一步打「比平均好多少」

仓库从最后一步往回扫（`tau` 就是公式里的 λ，这个实现默认 1.0）：

```python
# 对应 train.py 里 gae = 0; for value, reward, done in ...[::-1]
_, next_v = model(s)          # 第 513 步的 V，用来把最后一步补完
gae, advs = 0, []
for v, r, d in zip(reversed(values), reversed(rewards), reversed(dones)):
    # δ_t = r + γ V(s') (1-done) - V(s)
    delta = r + gamma * next_v * (1 - d) - v
    gae = delta + gamma * lam * (1 - d) * gae
    advs.append(gae)
    next_v = v
advs.reverse()
advs = torch.stack(advs)
returns = advs + torch.stack(values)   # V̂ = Â + V，给评论家当标签
```

对应：

$$
\delta_{t}=r_{t}+\gamma V(s_{t+1})(1-d_{t})-V(s_{t})
$$

$$
\hat{A}_{t}=\delta_{t}+\gamma\lambda(1-d_{t})\hat{A}_{t+1}
$$

马里奥：跳过坑，后面分高，`delta`、`gae` 都是正的，应多跳；掉坑 `done=1`，后面的 V 不算，这一下是负优势，应少这么按。`(1-d)` 在死的那步把后续截断。

## 五、更新：比值、clip、价值、熵

同一批数据回放若干 epoch。每次用**新**网络再算一遍这些旧动作的概率。

```python
# 对应 train.py 里 ratio / actor_loss / critic_loss / entropy
logits, value = model(states)
dist = Categorical(logits=logits)
new_log_pi = dist.log_prob(actions)

ratio = torch.exp(new_log_pi - old_log_pis)   # r_t(θ) = π_new / π_old
```

$$
r_{t}(\theta)=\exp\big(\log\pi_{\theta}(a_{t}\mid s_{t})-\log\pi_{\mathrm{old}}(a_{t}\mid s_{t})\big)
$$

`ratio = 1`：这个键的概率没变。`ratio > 1`：新策略更爱这么按。

Clip 目标（实现里取负号，因为优化器做的是**最小化**）：

```python
surr1 = ratio * advs
surr2 = ratio.clamp(1 - eps, 1 + eps) * advs   # eps=0.2
actor_loss = -torch.mean(torch.min(surr1, surr2))
```

$$
L^{\mathrm{CLIP}}=\mathbb{E}\big[\min\big(r_{t}\hat{A}_{t},\;\mathrm{clip}(r_{t},1-\varepsilon,1+\varepsilon)\hat{A}_{t}\big)\big]
$$

| 马里奥 | `advs` | 代码在干什么 |
|--------|--------|----------------|
| 跳过坑 | > 0 | 提高「跳」的 `ratio`，但 `clamp` 后最多 1.2 |
| 撞怪 | < 0 | 降低这个按法，但最低 0.8 |

`min` 再取负：不会比「裁过的保守版本」更贪。`ratio` 已经贴边时，梯度可以变成 0。

价值头拟合「这屏能拿多少」；熵避免永远只按右：

```python
critic_loss = F.smooth_l1_loss(value.squeeze(), returns)  # 仓库用 Huber，不是纯 MSE
entropy = dist.entropy().mean()
loss = actor_loss + critic_loss - 0.01 * entropy
loss.backward()
```

$$
L=L^{\mathrm{CLIP}}_{\mathrm{min}}+c_{1}L^{V}-c_{2}H[\pi]
$$

仓库里 `beta=0.01` 就是 c₂。熵前面是减号：熵越大损失越小，还敢试试跳。

## 六、一整轮在 train.py 里怎么走

```
reset 关卡
循环：
  1. 当前网络玩 512 步，记下 s, a, r, V, log π_old
  2. 从后往前扫，算出 Â 和 returns
  3. 打乱，切 batch，重复 10 个 epoch：
       新网络算 ratio、clip 策略损失、价值、熵
       Adam 一步
  4. 这批丢掉，带着新参数再进关
```

必须重新打：策略一改，旧录像就不是「当前打法」。epoch 太多等于又改猛了，clip 挡不住。

对照仓库默认超参：`gamma=0.9`，`epsilon=0.2`，`num_local_steps=512`，`num_epochs=10`，`num_processes=8`。

**一句话：** `sample` 用旧 π 打马里奥；`log_prob` 新旧相减得到 `ratio`；`clamp` 把好键的涨幅锁在 1±0.2；`value` 学这屏值多少；然后重新进 1-1。
